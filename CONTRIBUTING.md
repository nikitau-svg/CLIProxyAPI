# Изменения и баг-репорты Bravo

## Куда относится проблема

- Ошибка проектного ключа, `bravo/*` модели, fallback, русской диагностики,
  квот, аналитики или Management Center относится к Bravo и оформляется в
  этом репозитории.
- Ошибка, которая воспроизводится на чистом
  [CLIProxyAPI v7.2.94](https://github.com/router-for-me/CLIProxyAPI/tree/v7.2.94)
  без плагина Bravo, сначала сверяется с upstream.

## Что приложить к багу

1. Версию Bravo и commit контейнера/бинарника.
2. Протокол: Anthropic Messages, OpenAI Chat, Responses или Images.
3. Логическую модель `bravo/...` и клиент.
4. HTTP status, стабильный `code`, время и безопасный trace ID.
5. Минимальный воспроизводимый запрос без ключей, OAuth-токенов, cookies и
   приватного содержимого переписки.
6. Ожидаемое и фактическое поведение.

Нельзя публиковать `brv_...`, management key, provider credentials, содержимое
`auths/`, raw headers авторизации и несантированные provider JSON.

## Pull request

- База обычного изменения — `bravo/main`.
- Один PR должен решать одну проверяемую проблему.
- Изменение поведения сопровождается тестом и обновлением документации.
- Provider fallback не должен ослаблять project allowlist, разрешённый пул,
  capability-контракт или защиту секретов.
- Миграции persistent state должны быть обратно совместимыми либо иметь явный
  план отката.
- PR не означает разрешение на сборку production-контейнера или rollout.

Кандидаты адаптивного allocator 0.8.11 живут отдельно от stable 0.8.10 и не
должны незаметно попадать в `bravo/main`.
